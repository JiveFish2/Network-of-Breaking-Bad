## What this project is

A character-relationship network analysis of *Breaking Bad*. Adapted from `the_witcher_network` (Witcher version by thu-vu92). Pipeline:

1. **Scrape** the BB Fandom wiki for the canonical character list → `characters_bd.csv`.
2. **Extract relationships** from episode transcripts in `data/*.txt` via spaCy NER + a co-occurrence window.
3. **Build a graph** with NetworkX, visualise with pyvis, run centrality + Louvain community detection.

Two notebooks orchestrate this; reusable helpers live in `lib/utils/functions.py`.

## How the pipeline actually works

### `character_scraping.ipynb`
- Hits the MediaWiki API at `https://breakingbad.fandom.com/api.php` — no Selenium, no browser, no Cloudflare challenge.
- Discovers season subcategories under `Category:Breaking_Bad_Characters`, then pulls each season's pages with `cmtype=page` and pagination via `cmcontinue`.
- Normalises `Season 5A`/`5B` → `Season 5` to match the original schema.
- Writes deduplicated `characters_bd.csv`.

### `extracting_relationships.ipynb`
- Cell 0–1 imports + lib helpers up front so they're available throughout.
- Cell 2 (`!python3 -m spacy download en_core_web_sm`) is commented — one-time setup belongs in the README.
- Loads all 62 transcripts as one corpus → single spaCy doc → sentence-level entity lists.
- `clean_character_df()` strips parens, drops bit-parts rows, drops junk firstnames (titles, articles), injects Saul Goodman manually, and disambiguates Walter Jr.
- `normalize_entities()` resolves raw spaCy strings to canonical character names: alias map first, then exact full-name, then unique firstname only. Ambiguous firstnames (shared by >1 character) are dropped, not guessed.
- `create_relationships()` builds the windowed co-occurrence edge list.
- Centrality + Louvain community detection (uses `python-louvain`, imported as `community`).
- Final per-episode loop builds one graph per episode and tracks degree-centrality evolution for the main cast.

## Important design decisions

**Aliases are the resolution mechanism, not firstname-splitting.** The original notebook split entity strings to first-word and matched against `character_firstname`. That conflated Walter Sr./Jr. and silently dropped surname mentions. The current pipeline resolves *raw* entity strings via `ALIASES` first, returning canonical full names. Firstname matching is a fallback that only fires when the firstname is unique across the character list.

**Walter Jr. is reached only via aliases.** His row's `character_firstname` is overridden to `"Junior"` in `clean_character_df()`. So a bare `"Walter"` in dialogue attributes to Sr. (correct in 99% of show usage), and Jr. is reached via `Flynn` / `Walt Jr.` / `Junior` aliases.

**`Saul Goodman` is injected by `clean_character_df()`.** The Fandom *Breaking Bad Characters* category lists him under his Better Call Saul namespace (`Jimmy McGill`), so the BB scrape misses him entirely. The cleanup function adds him as a known fixture.

**Canonical names sometimes don't match colloquial usage.** The CSV has `Steven Gomez` (not Steve), `Gustavo Fring` (not Gus), `Walter White Jr.` (not Flynn). The alias map bridges show-dialogue forms to CSV canonical forms — extend the map rather than renaming CSV rows.

**spaCy model is cached.** `lib/utils/functions.py:ner()` caches the loaded model at module level and accepts an optional `nlp=` param. The per-episode loop now passes the preloaded `nlp` so it doesn't reload 62 times.

**`create_relationships()` is the single source of truth.** Both the corpus pipeline and the per-episode loop call it. Earlier notebook had a duplicated inline loop; that's now a no-op marker.

**The co-occurrence window is measured in TRANSCRIPT sentences, via `sentence_id`.** This is the single easiest thing to break in this codebase, so read it before touching the pipeline. `get_ne_list_per_sentence()` stamps every sentence with its position in the document. Downstream code then filters out sentences with no characters — but must **never renumber the surviving rows**. `create_relationships()` windows on `sentence_id` (falling back to the index only when the column is absent), so "window_size=5" keeps meaning "within 5 sentences of each other in the episode".

If the rows get renumbered, the window silently changes meaning to "the next 5 sentences that happen to mention *somebody*", which can span hundreds of lines of dialogue. Nothing errors; the graph just quietly turns into a hairball. That is exactly what FIX 11 repaired. Guard: a full-corpus run should land near **89 nodes / 236 edges / avg degree 5.3**. If you see ~102 nodes / ~362 edges / avg degree ~7.1, the sentence positions were lost.

**Two pyvis outputs are written, not one.** `breaking_basic.html` (degree-sized) and `breaking_communities.html` (Louvain-coloured). Original code wrote both to `breaking.html`, silently overwriting.

## Gotchas to watch for

- **The virtualenv is `.venv/`** (git-ignored), created 2026-10-21 per the README. It replaced a `bin/` venv at the repo root whose scripts had shebangs pointing at the folder's old locations, so `bin/jupyter` etc. no longer ran. If the project folder moves again, recreate `.venv` rather than patching it — venv scripts hardcode absolute paths.
- **`lib/` is project source AND vendored JS assets.** The pyvis-bundled `lib/tom-select`, `lib/vis-9.1.2`, `lib/bindings` are required at runtime for the HTML viz. Don't blanket-ignore `lib/`.
- **The notebook still has a local `def filter_entity(...)` in cell 16** that shadows the imported version. It's dead code (nothing calls it after FIX 3) but kept for now to minimise the diff. Safe to delete in a future cleanup pass.
- **Single-word minor characters (Lester, Stan, Ken, Bob, ...)** are matched by exact firstname and will accept any spaCy hit on those tokens. Acceptable noise; can be tightened later by promoting them to alias-only matching.
- **Hank Schrader didn't show up in pilot smoke-test mentions** despite being in the episode. spaCy `en_core_web_sm` sometimes misses short single-name tokens in transcript-style text. If higher-fidelity matching becomes important, upgrade to `en_core_web_lg` or `en_core_web_trf`.
- **`extracting_relationships.ipynb` weighs ~10 MB** because it embeds rendered graph outputs. Clearing outputs before committing will keep the repo lean if that becomes a concern.

## When extending

- **Adding more aliases** → edit `ALIASES` in `lib/utils/functions.py`. Targets must exist in `characters_bd.csv` (or be injected via `clean_character_df()`'s `extras` list).
- **Improving NER** → swap model in `ner()`. The cache means the change applies to all callers.
- **Adding a new relationship-extraction strategy** → add alongside `create_relationships()`; both notebook cells call it by name so they'll pick up changes.
- **Changing window size** → it's the `window_size` argument; default 5 is hardcoded in two places (corpus and per-episode loops). Consolidate if you want a single knob.
